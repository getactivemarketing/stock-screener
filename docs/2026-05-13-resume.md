### 5. After 5 trading days in shadow, decide on enforcement

Run the measurement query from the spec:

```sql
SELECT
  td.veto_verdict,
  COUNT(*) AS n,
  ROUND(100.0 * AVG(CASE WHEN sr.return_5d > 0 THEN 1 ELSE 0 END), 1) AS win_rate_pct,
  ROUND(AVG(sr.return_5d)::numeric, 2) AS avg_5d_return_pct
FROM trade_decisions td
JOIN scan_results sr ON sr.ticker = td.ticker AND sr.run_id = td.run_id
WHERE td.veto_verdict IS NOT NULL AND sr.return_5d IS NOT NULL
GROUP BY td.veto_verdict;
```

If `veto` cohort has ≥15 pp lower win rate than `confirm` cohort AND negative avg 5d return → enable enforcement:

```sql
UPDATE trading_config SET veto_layer_enforce = TRUE WHERE id = 1;
```

## Known issues to track (not blocking)

### Three veto-quality follow-ups (must fix before flipping enforce=TRUE)

1. **Veto sees null enrichment data**: `UnifiedPipelineResult` drops `ClassifierEnrichment`. The veto operates blind on analyst targets, days-to-earnings, and news headlines — about 60% of its designed signal is missing. Path: extend `UnifiedPipelineResult` to carry `enrichment?: ClassifierEnrichment` and plumb through `pipeline-unified.ts` line ~624.

2. **Shadow-log SKIP rows for confirmed BUYs inflate SKIP counts** in `trade_decisions`. The CHECK constraint is `action IN ('HOLD','SKIP')` — confirmed BUYs that the veto approved get a parallel `action='SKIP'` row with `veto_verdict='confirm'`. Operationally ugly. Cleanest fix: add `veto_shadow BOOLEAN` to `trade_decisions` in a follow-up migration, OR widen the CHECK to include a `'BUY_SHADOW'` value.

3. **`vetoFailed` field computed but never persisted** — the `confidence=0` signal in `FAIL_OPEN_RESULT` is a proxy, but adding a `veto_failed BOOLEAN` column would make this explicit.

### Reconciliation bug — 26 stale positions

`portfolio_state` shows 26 rows with `quantity > 0` going back to Apr 8 (OMEX -27%, OTLK -11%, etc.). Risk validation uses Alpaca's live position count (not the DB), so this isn't blocking trades. But analytics that read `portfolio_state` are wrong. Fix: either truncate stale rows, or wire the reconciliation loop that's supposed to mark closed positions as quantity=0. Investigate `reconcilePendingOrders` in `trader.ts:73`.

### Threshold tuning needs revisit

Threshold dropped 45 → 40 on the assumption that the existing FP problem is acceptable for now. **If trades start firing but P&L stays bad, drop further (38 catches ~7 BUYs/day) or revert to 45 and rely on sector pass for fresh signal.** Watch trades over the next 3-5 days before deciding.
